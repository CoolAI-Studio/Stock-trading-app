照著做就好。

約十五分鐘。手邊要有第 2 步的連線字串， 還有第 1 步的金鑰（沒有也行）。

  1. 建立服務

    按這顆按鈕，用 GitHub 帳號登入 Render，它會照著設定檔幫你建好。

    在 Render 建立後端

    畫面上會問我什麼？
    1. DATABASE_URL — 貼第 2 步那串 postgresql://…
    2. AI_API_KEY — 貼第 1 步那串 sk-or-v1-…。沒有就留空
    3. AI_MODEL — 留空
    4. 其他每一格都留空，包括看起來很重要的那些

    留空不是偷懶。加密金鑰那幾格等一下在系統的網頁上按按鈕產生， 不用在你自己的電腦上裝任何東西。

    不想用 Render — Railway 怎麼做
    1. 開 railway.app，用 GitHub 登入。
    2. New Project → Deploy from GitHub repo， 選這個專案（先在 GitHub 上按 Fork 複製一份到你的帳號）。
    3. Settings → Root Directory 留空 （就是專案根目錄）。
    4. Variables 加上 RAILWAY_DOCKERFILE_PATH = backend/Dockerfile，還有 DATABASE_URL （和選填的 AI_API_KEY）。
    5. Settings → Generate Domain，拿到你的後端網址。

    畫面偶爾會改版，找不到就找「Root Directory」和 「Variables」這兩個字。

    Root Directory 不可以填 backend： 這一個映像檔同時要建畫面和 API，所以它得同時看得到 frontend/ 和 backend/ 兩個資料夾。填了的話 build 會失敗在 requirements.lock 找不到。

    不想用 Render — Fly.io 怎麼做
    1. 裝 flyctl，然後 fly auth signup。
    2. 下載這個專案，在專案根目錄執行 fly launch --dockerfile backend/Dockerfile。 （不要進 backend 資料夾：這一個映像檔 同時要建畫面和 API，兩個資料夾都要看得到。）
    3. 它問要不要建資料庫時選 Yes，Fly 會自己設好 DATABASE_URL。
    4. fly deploy。

    這條路要打指令。不習慣終端機的話用上面兩家。

    不想用 Render — 我自己有一台機器
    1. 那台機器要裝 Docker。
    2. 下載這個專案，在專案根目錄執行 docker build -f backend/Dockerfile -t stock-alerts .
    3. docker run -p 8000:8000 -e DATABASE_URL=… stock-alerts

    要從外面連得到的話，那台機器需要一個對外網址和 HTTPS。

  2. 抄下你的網址

    建好之後 Render 會給你一個 https://xxx.onrender.com，在頁面最上面。複製它。

    第一次啟動要等三到五分鐘。中間看到錯誤畫面是正常的。

  3. 打開你的網址

    就是上一步那個網址——畫面和 API 是同一個，不用再部署一次。 你會直接看到建立帳號的畫面：加密金鑰、登入密鑰、推播金鑰 都是自動的，沒有東西要你複製貼上。

    它把我帶到「設定頁」而不是建立帳號

    代表真的還缺一格——最常見的是 DATABASE_URL 打錯或沒填，因為那是唯一一個 這個 app 生不出來的值（資料庫在別人家）。

    那一頁會列出缺什麼、不補會怎樣。能自己產生的旁邊有一顆 「產生」按鈕：按一下、複製、回 Render 後台點你的服務、 左邊選單 Environment、找到同名的那一格 貼進去、按 Save。Render 會自動重新部署，約兩分鐘， 然後回設定頁重新整理。

    還有一格叫 CORS_ORIGINS：留空就好。 畫面和 API 是同一個網址，所以沒有跨來源的問題。只有把畫面另外放在別家的人才要填。

    我想把畫面放在別家（Vercel、Netlify、Cloudflare…）

    可以，這條路沒有被拿掉——拿掉的只是「必須再部署一次」。

    1. 把 frontend/ 部署到你想用的那一家
    2. 設一個環境變數 VITE_API_BASE_URL， 值是上一步的後端網址，結尾不要有斜線
    3. 回後端的平台，把 CORS_ORIGINS 設成你新的前端網址

    分開放的話，更新要各更新一次：後端會自己更新， 而畫面那一份由你自己的平台決定。系統狀態頁會告訴你兩邊各是哪一版。

  4. 建立你的帳號

    設定頁說完成之後重新整理，畫面會請你建立帳號—— 第一個也是唯一一個。建好之後註冊自動關閉。

  5. 接上通知

    進去之後系統會帶你走引導：資料庫、AI、通知。 每一格都要按到「通了」為止，填了不算。

我要跑在自己的電腦上，不用雲端
  1. 裝 Docker Desktop。
  2. 下載這個專案（GitHub 頁面上綠色的 Code → Download ZIP），解壓縮。
  3. 在那個資料夾裡開終端機，輸入 docker compose up。
  4. 瀏覽器開 http://localhost:8000，從上面第 4 步繼續。

資料會存在你電腦上的一個檔案裡。電腦關機或睡著，盯盤就停了。

卡住了

卡住了？問 AI（有金鑰就直接問，沒有也能問）
畫面說「讀不到歷史資料」或一片空白

多半是後端還在醒（免費方案閒置後會休眠，冷啟動約一分鐘）。等一下重新整理。 一直這樣的話，看看 CORS_ORIGINS 是不是填了你的前端網址。

設定頁說資料庫連不上

連線字串多半貼漏了或密碼沒換。用 Supabase 的話，檢查那串裡的 [YOUR-PASSWORD] 有沒有換成你設的密碼。回資料庫服務重新複製一次最快。

還是不行

每一個設定值的完整說明在 部署說明； 真的卡住可以到 Issues 問。
